# Architecture

## Pipeline

```
 candidate (data/*/candidates.json)
     │
     ▼
 curated official videos (data/*/videos.json, hand-picked per candidate)
     │
     ▼
 official captions / published transcript  ──►  data/transcripts/<video_id>.json
     │      (NEVER generated by Gemini: that would make verification circular)
     ▼
 ┌───────────────────────── propose (modeled) ─────────────────────────┐
 │  ONRECORD_MODE=llm      Gemini → JSON [{topic_id, quote_text,       │
 │                          start_sec, end_sec, reason}]  (llm.py)     │
 │  ONRECORD_MODE=keyword  phrase match against topic example_phrases  │
 │                          (keyword_match.py)   ← also the LLM fallback│
 └─────────────────────────────────────────────────────────────────────┘
     │
     ▼
 verify (verify.py): quote must be in transcript (exact or near-exact, see D6)
     │   ├─ fail → DROP (never shown)
     │   └─ pass → quote_text := transcript words, start/end := real timestamps,
     │            context_before/after := neighbouring transcript text
     ▼
 Statement / clip card  (label: measured; topic assignment: modeled)
     │
     ▼
 API (main.py): all matches, chronological, + coverage counts,
                + unevenness warning, + empty state
     │
     ▼
 UI (frontend/): identical card format for every candidate; link/embed the
                 official player at start_sec; report-a-problem link
```

## Modules

| File | Role |
|---|---|
| `backend/models.py` | Pydantic schemas: Candidate, Video, Topic, Statement, API responses |
| `backend/config.py` | Paths, mode, thresholds (single place for all tunables) |
| `backend/storage.py` | Load JSON from `ONRECORD_DATA_DIR` and `config/topics.json` |
| `backend/verify.py` | Normalization + verbatim verification + timestamp correction + context |
| `backend/keyword_match.py` | No-LLM proposer |
| `backend/llm.py` | `MomentProposer` interface, `GeminiProposer`, `FakeProposer` (tests) |
| `backend/pipeline.py` | propose → verify → Statement; coverage; empty state; unevenness |
| `backend/main.py` | FastAPI app |
| `frontend/` | Vite + React, plain JS |

## API (v0)

| Method | Path | Purpose |
|---|---|---|
| GET | `/health` | liveness + current mode |
| GET | `/candidates` | candidates with coverage counts + unevenness warning |
| GET | `/topics` | fixed checklist |
| GET | `/candidates/{id}/topics/{topic_id}` | all verified clip cards (chronological) or empty state |
| POST | `/verify` | strict check: does this quote appear in this video's transcript? (demo) |
| POST | `/reports` | report a problem → appended to `data/reports/reports.jsonl` (no user data) |

## Neutrality guarantees in code

- One code path for all candidates; `party` is display-only and never read by the pipeline.
- Response models contain no score/rating/rank fields (enforced by `tests/test_no_scores.py`).
- Cards are sorted only by `(published_date, start_sec)`.
